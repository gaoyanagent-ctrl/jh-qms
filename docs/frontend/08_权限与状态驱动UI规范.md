# 权限与状态驱动 UI 规范

## 1. 目标

IAF 前端按钮、字段、菜单、页面和业务动作必须由权限、状态、字段权限和视图模式共同控制。

## 2. 权限类型

- 菜单权限
- 路由权限
- 按钮权限
- API 权限提示
- 字段权限
- 审批节点字段权限
- 外部用户权限

## 3. 标准组件

```text
PermissionGuard
PermissionRoute
PermissionButton
FieldPermissionWrapper
BusinessActionBar
StateTransitionButton
```

## 4. 权限按钮

```tsx
<PermissionButton permission="wms:receipt:create">
  {t('common.action.create')}
</PermissionButton>
```

页面中不得写：

```tsx
{permissions.includes('wms:receipt:create') && <Button>新增</Button>}
```

## 5. 字段权限

字段权限必须统一处理：

```tsx
<FieldPermissionWrapper object="wms.receipt" field="costAmount">
  <ProFormDigit name="costAmount" />
</FieldPermissionWrapper>
```

字段权限结果：

```text
VISIBLE_EDITABLE
VISIBLE_READONLY
HIDDEN
MASKED
```

## 6. 业务动作可用性

按钮不能只看权限，还要看状态。

例如确认收货：

```text
权限：wms:receipt:confirm
单据状态：EFFECTIVE
收货状态：不是 FULL_RECEIVED
过账状态：NOT_POSTED
```

必须通过：

```text
useBusinessActions
BusinessActionBar
ActionAvailability
```

## 7. 状态展示

所有业务状态必须用统一组件：

- StatusTag
- BusinessStatusBadge
- DocumentStatusTag
- ApprovalStatusTag
- ExecutionStatusTag
- InventoryStatusTag
- TaskStatusTag

禁止页面自行拼接颜色和文案。

当前实现入口：`frontend/packages/ui-core/src/index.tsx`。颜色必须来自 `@iaf/theme` 的 semantic token，不允许业务页面单独维护状态颜色表。
