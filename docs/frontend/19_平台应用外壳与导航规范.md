# 平台应用外壳与导航规范

## 1. 目标

本规范定义 IAF PC 管理端的应用外壳、左侧导航、顶部栏、用户档案入口、全局搜索和外壳级偏好能力。

应用外壳是所有平台页面、Kanban、流程编辑器、审批流编辑器和后续 WMS 页面共享的基础结构。单个业务页面不得私自实现另一套导航、用户菜单、主题切换或侧栏行为。

## 2. IAOS 参考结论

参考 `/iaos/iaos-go/frontend/src/components/layout/Sidebar.tsx`、`MainLayout.tsx`、`IaosLogo.tsx` 和 `useAuth.ts` 后，IAF 可吸收以下设计方向：

- 品牌区、租户/组织上下文、菜单分组、主题切换、语言切换、用户档案可以在应用外壳中形成稳定入口。
- 左侧导航需要同时支持展开态和折叠态，折叠态保留图标、Tooltip 和用户入口。
- 用户档案状态应包含 displayName、avatarUrl、tenantLogoUrl、tenant/org 上下文，不应只显示用户名文本。
- 工业科技感可通过 token、边界、状态点、图标和密度体现，不需要把普通管理页面做成大屏页面。
- IAOS 的 Tailwind 类名和具体实现不直接复制；IAF 必须适配 Ant Design、ProComponents、ThemeProvider 和本项目 token 体系。

## 3. 标准外壳结构

PC 管理端默认结构：

```text
┌────────────────────────────────────────────────────────────────────┐
│ 顶部栏：全局搜索 / 当前组织 / 主题 / 语言 / 通知 / 用户档案 / AI入口 │
├────────────────┬───────────────────────────────────────────────────┤
│ 左侧导航        │ 多标签页 / 页面标题 / 页面内容                    │
│ 品牌区          │                                                   │
│ 菜单搜索        │                                                   │
│ 分组菜单        │                                                   │
│ 底部用户快捷区  │                                                   │
└────────────────┴───────────────────────────────────────────────────┘
```

规则：

- 应用外壳由 `pc-admin` 布局层统一实现。
- 页面组件只能声明 PageContext、菜单 key、标题、权限和页面类型。
- 菜单、路由、权限、用户档案、主题、语言、组织切换必须由外壳或共享 store 注入。
- 大屏查看端可使用专用全屏 shell，但从 PC 管理端进入编辑和管理时仍遵循本规范。

## 4. 左侧导航

展开态：

- 默认宽度 248px。
- 最小宽度 220px。
- 最大宽度 360px。
- 支持拖拽改变宽度，拖拽柄位于侧栏和内容区之间。
- 宽度按用户、租户和终端类型持久化。

折叠态：

- 宽度 64px 到 72px。
- 只显示图标、活动状态和必要状态点。
- 菜单名称通过 Tooltip 或浮层展示。
- 折叠状态按用户持久化。
- 折叠后仍必须能访问菜单搜索、用户档案、主题/语言切换的紧凑入口。

菜单分组：

- 默认分组为工作台、平台管理、制造主数据、WMS、流程审批、报表与大屏、系统配置。
- 每个分组使用图标和轻量标题；不得使用大面积彩色块造成噪音。
- 活动菜单使用主色左边界、浅背景或文本主色，不同时使用过多强调样式。
- 菜单可显示权限控制后的项；前端隐藏不是安全边界，后端仍必须校验权限。

## 5. 侧栏搜索

侧栏必须提供菜单搜索：

- 展开态在品牌区下方显示搜索框。
- 折叠态显示搜索图标，点击后打开浮层或命令面板。
- 支持按菜单名称、路由、权限码、模块名搜索。
- 支持键盘上下选择和回车打开。
- 无结果时展示可理解空态，不展示创建入口。
- 搜索结果必须受菜单权限过滤。

后续可扩展全局命令面板，但不能替代侧栏菜单搜索。

## 6. 顶部栏

顶部栏高度 56px 到 64px。

必须包含：

- 全局搜索入口或命令面板入口。
- 当前组织、工厂、仓库或租户上下文，按业务阶段启用。
- 主题切换。
- 语言切换。
- 简洁/专家模式切换。
- 通知入口。
- 用户档案菜单。
- AI 助手入口，按权限和配置显示。

规则：

- 顶部栏不放页面级业务按钮；业务按钮属于页面标题区或页面工具栏。
- 技术状态徽标仅在专家模式、运维视图或系统健康页面展示，普通用户默认隐藏。
- 顶部栏和侧栏不能重复展示所有入口；用户档案默认在右上角，侧栏底部可提供紧凑快捷入口。

## 7. 用户档案入口

推荐默认位置为顶部栏右侧。

内容：

- 头像。
- 用户显示名。
- 当前租户/组织简称。
- 在线或会话状态，按需。
- 菜单项：个人中心、偏好设置、主题与密度、组织切换、语言切换、退出登录。

侧栏底部可显示紧凑用户区：

- 展开态显示头像、displayName、tenant/org 简称。
- 折叠态只显示头像，并通过 Dropdown 打开完整菜单。
- 当顶部栏空间充足时，侧栏底部用户区可只保留快捷入口，避免重复信息过多。
- 侧栏高度必须锁定在视口高度内，菜单区独立滚动，底部用户区不得被右侧长表单、长抽屉或页面内容撑到屏幕外。

品牌和用户档案来源：

- Logo、品牌名、登录背景、主色来自品牌配置或主题配置。
- displayName、avatarUrl、tenantLogoUrl、tenant/org 名称来自认证上下文或用户配置接口。
- 不允许在布局组件中硬编码客户名、租户名、用户头像或品牌文案。

## 8. 外壳级偏好

以下偏好必须由外壳统一管理：

- 主题。
- 密度。
- 简洁/专家模式。
- 新增/编辑展示模式：Modal、Drawer、独立页面。
- 侧栏折叠状态。
- 侧栏宽度。
- 最近访问和常用功能。

实现要求：

- 侧栏折叠状态和侧栏宽度必须进入用户体验偏好，并随 `/api/platform/preferences/me` 保存。
- 拖拽宽度时可先本地即时响应，完成拖拽后写入统一偏好状态。
- 偏好重置必须同时恢复主题、密度、表单模式、侧栏折叠状态和侧栏宽度。

持久化优先级：

1. 页面或业务对象强约束。
2. 管理员配置。
3. 主题默认值。
4. 用户偏好。
5. 系统默认值。

## 9. 与复杂视图关系

- Kanban 默认仍在标准 shell 内运行，但可使用更强工业状态色和密度。
- 流程编辑器、审批流编辑器默认在标准 shell 内使用独立页面，画布区域最大化。
- 大屏查看可进入全屏 shell；大屏编辑器仍保留返回、保存、发布、预览等管理操作。
- 外壳宽度变化、侧栏折叠和 AI 面板打开不得破坏画布、表格和 Kanban 的最小可用宽度。

## 10. 当前决策记录

已采纳：

- 平台 PC 端必须有统一应用外壳，业务页面不得重复实现导航和用户菜单。
- 左侧导航支持搜索、折叠和拖拽改变宽度。
- 用户档案默认放在右上角，侧栏底部可提供紧凑快捷入口。
- 品牌、用户档案、租户/组织上下文必须来自配置或认证上下文。
- IAOS 作为布局丰富度和工业科技感参考，不作为代码复制来源。

暂不采用：

- 所有入口都堆在侧栏底部。
- 普通管理页面默认全屏大屏风格。
- 每个业务模块自行实现侧栏、顶部栏、主题切换或用户菜单。

## 11. 长期治理

应用外壳是 Platform Foundation RC1 的稳定契约。后续 Agent 修改导航、顶部栏、菜单、标签页或偏好能力时必须遵守：

- 不得在业务页面重复实现侧栏、顶部栏、主题切换、语言切换、用户菜单或标签页状态。
- 菜单 code、route path、permission code 和 i18n title key 变更必须同步交付包、code map 和发布清单。
- 外壳级偏好必须继续通过 `/api/platform/preferences/me` 或统一偏好适配层持久化。
- 侧栏折叠、宽度拖拽、菜单搜索、用户档案和多标签页必须覆盖空态、loading、权限过滤和小屏可用性。
- 顶部栏不得承载页面级业务按钮；页面级动作必须放在页面标题区、工具栏或标准操作区。
- 大屏、Kanban、设计器可以强化视觉语言，但返回管理端编辑或配置时仍必须遵守标准 shell。
- 任何破坏兼容的外壳改动必须在 `docs/operations/platform-foundation-release-checklist.md` 记录风险，并按需新增 ADR。

RC1 反馈稳定期补充：

- 外壳反馈统一记录到 `docs/operations/platform-foundation-feedback-log.md`，至少包含菜单、路由、权限、偏好、标签页或顶部栏入口中的具体对象。
- 侧栏折叠、宽度、用户偏好、菜单搜索和标签页问题如果导致核心平台页面不可达，按 P1 处理。
- 偏好保存相关脚本或页面逻辑必须保留已有用户设置；除非 API 明确是 merge 语义，否则调用方需要先读出完整 settings 后再写回。
- 业务领域页面开始开发前，外壳必须满足 `docs/operations/platform-foundation-stabilization-plan.md` 的进入条件。
