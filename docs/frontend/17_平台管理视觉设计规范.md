# 平台管理视觉设计规范

## 1. 目标

定义 IAF 平台管理端的视觉方向、主题、配色、密度、组件外观和品牌化策略。

本规范用于指导 `TASK-0204` 和 `TASK-0207`，也用于约束后续所有平台管理页面。

## 2. 视觉定位

IAF 是工业企业应用框架，视觉应体现：

- 稳定。
- 专业。
- 清晰。
- 高效。
- 可长期使用。
- 工业制造场景感。
- 监控调度场景的科技感。

不采用：

- 大面积渐变背景。
- 过度装饰。
- 营销页式 hero。
- 卡片堆叠式低密度后台。
- 单一蓝紫色调主导整个系统。

IAF 的视觉不是在“企业后台专业工具风”和“工业制造感 / 大屏感 / 科技感”之间二选一，而是按用户、功能和使用场景分层：

| 场景 | 主要用户 | 视觉方向 |
|---|---|---|
| 平台日常管理 | 管理员、实施顾问、运维人员 | 企业后台专业工具风，强调效率、密度、可预测操作 |
| 业务配置与主数据 | 业务主管、关键用户 | 专业后台为主，适度体现工业语义和状态感 |
| Kanban、调度、异常处理 | 班组长、调度员、现场主管 | 强化工业制造感，信息密度高，状态与优先级突出 |
| 大屏查看、控制室、监控中心 | 管理层、控制室、展示屏 | 强化大屏感和科技感，暗色、高对比、远距离可读 |
| 设计器、流程/审批编辑器 | 平台管理员、实施顾问、流程负责人 | 专业工具型界面，局部使用科技感强化画布和节点状态 |

规则：

- 标准 CRUD 页面不做大屏化，不牺牲录入和管理效率。
- Kanban、调度、监控、大屏、设计器可以使用更强的工业和科技视觉语言。
- 同一用户可在不同功能内看到不同视觉强度，但基础导航、权限、状态、组件行为必须一致。
- 视觉强度由主题、页面类型、密度和组件 token 共同决定，不允许单个页面硬编码一套风格。

## 3. 默认主题方向

第一版必须至少实现两个可切换主题，用于验证主题切换、token 覆盖和用户偏好持久化：

| 主题 | 定位 | 默认使用场景 |
|---|---|---|
| `light-industrial` | 浅色工业后台主题 | 平台日常管理、主数据、配置、表单录入 |
| `dark-industrial` | 暗色工业科技主题 | Kanban、监控、调度、大屏预览、控制室模式 |

默认 PC 管理主题为 `light-industrial`。`dark-industrial` 必须与其共用同一套语义 token，不允许复制一套页面样式。

视觉特征：

- 浅色背景。
- 清晰边界。
- 中性灰为底。
- 品牌色用于主操作和焦点。
- 业务状态使用语义色，不与品牌色混用。
- 页面密度偏紧凑。

推荐基础色板：

| Token | 用途 | 建议 |
|---|---|---|
| colorPrimary | 主按钮、焦点、选中态 | 稳定蓝或青蓝 |
| colorSuccess | 成功、完成、启用 | 绿色 |
| colorWarning | 待处理、冻结、预警 | 琥珀色 |
| colorError | 失败、拒绝、危险 | 红色 |
| colorInfo | 信息提示 | 蓝灰 |
| colorBgLayout | 页面背景 | 浅灰 |
| colorBgContainer | 内容容器 | 白色 |
| colorBorder | 边框 | 中性灰 |

禁止：

- 在业务页面直接写十六进制颜色。
- 用主色表达所有状态。
- 用状态色装饰无关 UI。

## 4. 配色协调规则

IAF 主题配色必须遵循“中性底色 + 工业品牌色 + 语义状态色”的体系，避免页面像多个组件库拼在一起。

比例：

- 70%：中性背景、容器、边框、正文文本。
- 20%：品牌主色、选中态、焦点态、主按钮。
- 10%：业务状态色、告警、数据可视化重点色。

`light-industrial` 推荐方向：

| 色彩角色 | 方向 |
|---|---|
| 中性底色 | 冷灰、浅蓝灰、低饱和白，不使用暖米色作为主背景 |
| 品牌主色 | 稳定工业蓝或青蓝，用于主操作和焦点 |
| 辅助强调 | 少量青绿或电气青，用于科技感状态点、关键指标 |
| 边框 | 低对比蓝灰边框，保证表格和抽屉边界清楚 |
| 文本 | 深灰蓝正文，弱文本使用灰蓝，不使用纯黑大面积铺开 |

`dark-industrial` 推荐方向：

| 色彩角色 | 方向 |
|---|---|
| 中性底色 | 深蓝灰、石墨灰，避免纯黑 |
| 容器 | 与背景拉开 4% 到 8% 明度差 |
| 品牌主色 | 更亮的青蓝，用于选中、焦点、主按钮 |
| 状态色 | 提升亮度但降低面积，确保远距离可读 |
| 图表色 | 使用固定数据色板，不能随机取主题主色变体 |

Token 分组：

- Brand：`colorPrimary`、`colorPrimaryHover`、`colorPrimaryActive`、`colorFocusBorder`。
- Surface：`colorBgLayout`、`colorBgContainer`、`colorBgElevated`、`colorFillSecondary`。
- Border：`colorBorder`、`colorSplit`、`colorBorderSecondary`。
- Text：`colorText`、`colorTextSecondary`、`colorTextTertiary`、`colorTextDisabled`。
- Semantic：success、warning、error、info、processing、neutral。
- Shell：sidebar 背景、sidebar active、topbar 背景、resize handle、menu hover。
- DataViz：图表分类色、连续色、异常色、预测色。

规则：

- 同一页面最多使用一个品牌主色和一个辅助强调色。
- 状态色只能表达状态，不用于装饰背景。
- 组件 hover、active、selected 必须从 token 派生，不能由页面自行调色。
- 客户品牌主题可覆盖主色和 Logo，但不得破坏语义状态色。
- 图表色板必须与主题色协调，但不等于主色深浅变体集合。

## 5. 主题类型

必须规划以下主题，其中第一版至少落地 `light-industrial` 和 `dark-industrial`：

| 主题 | 用途 |
|---|---|
| light-industrial | 默认 PC 管理端 |
| dark-industrial | 工业科技暗色主题，Kanban、监控、设计器和大屏预览优先 |
| dark-ops | 夜间监控、控制室，后续可由 dark-industrial 扩展 |
| compact | 高密度数据录入 |
| dashboard | 大屏看板 |
| mobile-work | 移动作业 |
| high-contrast | 高对比辅助 |
| customer-brand | 客户品牌主题 |

## 6. 密度

PC 管理端默认使用标准偏紧凑密度。

| 密度 | 场景 |
|---|---|
| comfortable | 工作台、详情、审批阅读 |
| standard | 默认平台页面 |
| compact | 列表、主数据、配置表 |
| operation | 作业页面 |
| dashboard | 大屏 |

规则：

- 表格默认 compact。
- 表单默认 standard。
- 详情默认 comfortable。
- 设计器使用工具型紧凑布局。
- Kanban 默认 standard 或 operation，由页面类型和用户偏好决定。
- 大屏查看使用 dashboard，不继承普通后台密度。

## 7. 布局规范

左侧菜单：

- 宽度默认 248px。
- 最小宽度 220px。
- 最大宽度 360px。
- 支持折叠。
- 支持拖拽改变宽度。
- 支持菜单搜索。
- 图标 + 文案。
- 当前菜单高亮清晰但不过度强调。
- 折叠态宽度 64px 到 72px，只显示图标、Tooltip 和必要状态点。
- 底部可放紧凑用户档案入口；完整用户档案默认放顶部栏右侧。

顶部栏：

- 高度 56px 到 64px。
- 放置组织/语言/主题/通知/用户。
- 不放过多业务按钮。
- 用户档案默认放右侧，包含头像、显示名、当前租户/组织和下拉菜单。
- 主题、语言、密度、简洁/专家模式属于外壳级偏好入口。

内容区：

- 页面背景使用 layout 背景。
- 内容容器使用白底或 token 容器色。
- 禁止页面区域无限卡片套卡片。
- 新增/编辑选择独立页面模式时，内容区显示表单工作区并隐藏列表主体。

详细应用外壳、侧栏搜索、折叠、拖拽宽度、用户档案规则见 `docs/frontend/19_平台应用外壳与导航规范.md`。

## 8. 组件外观

按钮：

- 主操作使用 primary。
- 次操作使用 default。
- 链接型操作只在表格操作列使用。
- 危险操作使用 danger，并且需要确认。

表格：

- 表头背景轻微区分。
- 行 hover 清晰。
- 固定操作列。
- 状态标签颜色来自 semantic token。

表单：

- Label 对齐统一。
- 必填项标记清楚。
- 错误信息在字段下方。
- 表单分组使用分割标题，不使用重装饰卡片。

详情：

- 摘要区突出编码、名称、状态、责任人。
- 详情块使用描述列表。
- 时间线用于审批、状态迁移、操作日志。

Modal / Drawer / 独立页面：

- Modal 默认不低于 `min(90vw, 760px)`，不得把普通新增/编辑做成窄弹窗。
- Drawer 默认不低于 `min(92vw, 960px)`，复杂配置可使用 `min(96vw, 1120px)`。
- Drawer header、body、footer 需要清晰分层；footer 固定，body 滚动。
- 独立页面表单应使用工作区布局，避免表单和列表同时挤在一个视图中。
- 尺寸、圆角、阴影、边框、遮罩透明度必须由主题 token 控制。

## 9. 登录页

登录页必须体现产品和客户品牌。

结构：

```text
左侧品牌区 / 背景图 / 工业场景视觉
右侧登录表单
```

规则：

- 品牌名、Logo、主色来自品牌配置。
- 背景可使用工业场景图或客户配置图。
- 不使用抽象渐变作为主要视觉。
- 登录错误显示统一错误文案。

## 10. 工作台

工作台不是营销首页，是工作入口。

应包含：

- 我的待办。
- 常用功能。
- 最近访问。
- 平台公告。
- 系统健康或同步状态，按权限显示。
- 快捷统计，按模块启用。

不应包含：

- 大面积欢迎 hero。
- 无操作价值的装饰卡片。

## 11. 设计决策记录

已采纳：

- 专业企业后台和工业科技视觉并存，按用户、功能和场景分层使用。
- 第一版至少实现 `light-industrial` 与 `dark-industrial` 两个可切换主题。
- 默认使用浅色工业后台主题处理日常平台管理。
- Kanban、监控、调度、大屏和设计器可使用更强工业制造感、大屏感和科技感。
- 支持暗黑、紧凑、大屏、移动、高对比和客户品牌主题的后续扩展。
- 页面密度偏高，适合企业管理和重复操作。
- 主题和品牌配置必须后端化。
- 主题配色采用中性底色、品牌主色、语义状态色分层，控制色彩比例和状态色用途。
- 左侧导航、顶部栏、用户档案、菜单搜索、侧栏折叠和侧栏拖拽宽度属于应用外壳标准能力。
- Modal、Drawer、独立页面的尺寸和视觉样式由主题 token 和交互规范统一。

暂不采纳：

- 以紫蓝渐变为主视觉。
- 每个模块独立配色体系。
- 纯 Ant Design 默认样式直接作为最终设计。
- 将所有平台管理页面统一做成大屏科技风。

## 12. 长期治理

Platform Foundation RC1 之后，本文件是平台管理视觉治理的规格来源。后续平台页和业务页必须保持以下约束：

- 颜色、间距、圆角、阴影、边框、状态色必须来自 Ant Design token 或 `@iaf/theme` 语义 token。
- 表格默认使用紧凑密度，标准管理页不得退化成低密度卡片堆叠。
- 新增/编辑必须使用统一的 Modal、Drawer 或独立页面策略，不得在页面内硬塞局部表单。
- 状态标签必须使用统一状态组件或语义 token，不得页面级自行拼接颜色。
- 图标优先使用项目已引入的图标体系，不得为常见操作重复制作一次性图标。
- 空态、错误态、loading、无权限态必须作为页面验收项，不能只覆盖 happy path。
- 标准列表和表单页面必须优先复用 table-engine、form-engine、FormInteractionSurface 和既有业务组件。
- 用户可见文案必须走 i18n key，不得在页面中硬编码中文或英文业务文案。

视觉回归治理：

- RC1 阶段允许使用截图验收清单和 `frontend/e2e/platform-pages-visual.spec.ts` 的页面覆盖作为基线。
- 后续如引入 Playwright screenshot baseline，必须控制快照范围，避免把非稳定动态内容作为阻塞差异。
- 普通平台管理页不得为了视觉回归通过而降低信息密度、隐藏错误态或移除权限态。

RC1 反馈稳定期治理：

- 页面视觉问题必须记录到 `docs/operations/platform-foundation-feedback-log.md`，并标注 P1/P2/P3、页面、状态和复现步骤。
- 视觉问题只有在影响登录、核心导航、核心平台页面可用性、权限识别或实施演示时才阻塞业务领域开工。
- P2/P3 视觉 polish 不得绕过 token、i18n、权限组件、table-engine/form-engine 或统一交互面。
- 后续截图基线变更必须说明是设计决策变化、组件修复还是环境差异，不能把不稳定动态内容纳入阻塞快照。
