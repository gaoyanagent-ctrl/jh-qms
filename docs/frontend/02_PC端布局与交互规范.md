# PC 端布局与交互规范

## 1. PC 端定位

PC 端同时承担后台管理、业务作业、审批处理、报表查看、低代码配置、设计器和 AI 辅助工作。

## 2. 标准布局

```text
┌─────────────────────────────────────────────────────────────┐
│ Logo | 应用切换 | 组织切换 | 全局搜索 | 语言 | 主题 | 用户 │
├───────────────┬─────────────────────────────────────────────┤
│ 左侧模块菜单   │ 多标签页 Tab Bar                            │
│               ├─────────────────────────────────────────────┤
│               │ 页面内容区                          AI 面板  │
└───────────────┴─────────────────────────────────────────────┘
```

## 3. 顶部工具栏

必须包含：

- 当前系统 / 应用名
- 当前组织 / 工厂 / 仓库切换
- 全局搜索入口
- 语言切换
- 主题切换
- 简洁 / 专家模式切换
- 消息通知
- 当前用户菜单
- AI 助手入口

## 4. 左侧菜单

菜单按模块组织：

```text
工作台
平台管理
制造主数据
WMS
MES（预留）
SRM（预留）
QMS（预留）
配置中心
报表中心
```

菜单显示必须由后端菜单权限和前端路由权限共同控制。

## 5. 页面类型

PC 页面统一分为：

| 类型 | 用途 | 模板 |
|---|---|---|
| 工作台页 | 用户入口与业务概览 | WorkspacePage |
| 列表页 | 查询、筛选、批量操作 | ConfigurableListPage |
| 表单页 | 新增、编辑、提交 | ConfigurableFormPage |
| 详情页 | 查看、操作、审批、日志 | BusinessDetailPage |
| 作业页 | 业务操作步骤 | OperationPage |
| 设计器页 | 流程、打印、条码、看板设计 | DesignerPage |
| 报表页 | 查询与图表分析 | ReportPage |

## 6. 操作区规则

页面操作按钮按优先级排列：

1. 主操作，例如提交、确认、保存。
2. 次操作，例如打印、导出、复制。
3. 危险操作，例如作废、删除、撤回。
4. 更多操作，低频动作放入下拉菜单。

危险操作必须二次确认，并显示业务影响。

## 7. 错误与提示

- 表单错误显示在字段附近。
- 业务错误必须显示用户能理解的业务语言。
- 系统错误显示错误码和可复制的追踪 ID。
- 长耗时操作必须显示进度或处理中状态。

## 8. 页面上下文

每个业务页面必须注册：

```ts
type PageContext = {
  module: string;
  pageType: 'list' | 'form' | 'detail' | 'operation' | 'designer';
  objectType?: string;
  objectId?: string;
  routePath: string;
};
```

该上下文用于多标签页、AI 助手、审计、用户偏好和帮助系统。
