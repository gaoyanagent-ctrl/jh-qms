# 复杂视图与设计器规范

## 1. 目标

定义 Kanban、大屏查看、大屏编辑器、流程编辑器、审批流编辑器等复杂前端能力的设计原则和交互方向。

这些能力属于平台能力，不属于 WMS 专属能力。

## 2. 通用原则

复杂视图必须具备：

- 明确的工具区。
- 明确的画布或主体区。
- 明确的属性区。
- 可撤销或可确认的高风险操作。
- 保存、预览、发布状态清晰。
- 权限控制。
- 版本记录，按任务需要启用。

复杂视图不使用普通 CRUD 页面模板，但必须遵守平台主题、i18n、权限和 code map 规则。

## 3. 实施优先级

复杂视图按以下优先级推进：

| 优先级 | 能力 | 原因 |
|---|---|---|
| P1 | Kanban 平台能力 | 覆盖审批、任务、异常、调度等多类业务，能较早验证工业制造感和状态驱动 UI |
| P1 | 流程编辑器 | 平台审批和后续业务流转的基础能力，需要尽早稳定模型和画布交互 |
| P1 | 审批流编辑器 | 与流程编辑器共享画布能力，但聚焦业务审批配置 |
| P2 | 大屏查看 | 在主题和数据组件稳定后实现展示端 |
| P2 | 大屏编辑器 | 交互复杂度高，依赖主题、图表、数据绑定、组件资产沉淀 |

## 4. Kanban 视图

适用场景：

- 审批任务。
- 项目任务。
- 生产任务。
- WMS/MES 作业任务。
- 异常处理。

布局：

```text
标题 / 筛选 / 视图切换
Kanban 列区域
卡片详情抽屉
```

列规则：

- 列代表状态、阶段、负责人或业务分类。
- 列头显示名称、数量、状态摘要。
- 支持横向滚动。
- 支持权限控制下的拖拽。

卡片规则：

- 卡片展示主标题、状态、责任人、时间、优先级。
- 卡片不展示过多字段。
- 点击打开详情抽屉。
- 拖拽触发状态变更时必须经过后端校验。

第一版不做：

- 自定义卡片模板设计器。
- 跨业务复杂数据聚合。

## 5. 大屏查看

大屏查看用于控制室、展示屏、运营监控。

布局：

- 全屏展示。
- 无普通后台菜单。
- 支持自动刷新。
- 支持全屏播放。
- 支持发布版本读取。

组件：

- 指标卡。
- 折线图。
- 柱状图。
- 饼图。
- 表格。
- 排行榜。
- 文本。
- 图片。
- iframe。

视觉：

- 使用 `dashboard` 主题。
- 暗色为默认方向。
- 强调对比度和远距离可读性。
- 不复用普通管理页密度。

## 6. 大屏编辑器

布局：

```text
顶部工具栏：保存 / 预览 / 发布 / 撤销 / 重做
左侧组件面板
中间画布
右侧属性面板
底部状态区，按需
```

画布规则：

- 支持拖拽组件。
- 支持移动、缩放。
- 支持对齐辅助线。
- 支持图层顺序。
- 支持画布尺寸配置。

属性面板：

- 基础属性。
- 样式属性。
- 数据绑定。
- 刷新策略。
- 权限或可见性，按需。

第一版数据源：

- Mock 数据。
- 固定 API 数据集。
- 简单 SQL/查询配置暂不开放给业务用户。

## 7. 流程编辑器

流程编辑器用于维护流程定义。

布局：

```text
顶部工具栏
左侧节点面板
中间流程画布
右侧节点属性
底部校验结果
```

节点类型第一版：

- 开始。
- 结束。
- 审批。
- 条件。
- 抄送。

操作：

- 拖拽节点。
- 连线。
- 删除。
- 复制。
- 校验。
- 保存草稿。
- 发布版本。

规则：

- 不直接暴露 Flowable 内部模型给业务模块。
- 保存为 IAF 审批定义模型。
- 发布前必须校验流程完整性。

## 8. 审批流编辑器

审批流编辑器聚焦业务审批配置，不追求完整 BPMN 复杂度。

配置内容：

- 节点名称。
- 审批人规则。
- 条件表达式。
- 字段权限。
- 动作权限。
- 超时策略，预留。
- 通知策略，预留。

审批人规则：

- 指定用户。
- 指定角色。
- 发起人主管。
- 组织负责人。
- 表单字段引用，预留。

字段权限：

- 可编辑。
- 只读。
- 隐藏。
- 脱敏。

## 9. 设计器状态

设计器对象必须具备：

- 草稿。
- 已发布。
- 已停用。
- 历史版本。

发布规则：

- 草稿可反复保存。
- 发布生成不可变版本。
- 已发布版本被业务实例引用后不得物理删除。

## 10. 当前决策记录

已采纳：

- Kanban、大屏、流程编辑器、审批流编辑器均作为平台能力。
- 实施优先级为 Kanban、流程编辑器、审批流编辑器优先；大屏查看和大屏编辑器后续推进。
- 大屏查看和大屏编辑分离。
- 流程编辑器和审批配置可以共享画布，但模型必须落到 IAF 平台模型。
- 复杂视图使用工具型布局，不套普通 CRUD 卡片模板。

暂不采纳：

- 第一版实现完整 BI。
- 第一版开放任意 SQL 给业务用户。
- 第一版覆盖全部 BPMN 高级能力。
- 在 Kanban 和流程/审批编辑器稳定前优先投入大屏编辑器重交互。
