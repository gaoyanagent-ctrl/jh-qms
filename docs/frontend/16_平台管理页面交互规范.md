# 平台管理页面交互规范

## 1. 目标

本规范定义 IAF 平台管理端的页面信息架构、查看/新增/编辑/操作方式和基础交互模式。

适用页面：

- 用户、组织、角色、菜单、权限、字典、参数、操作日志。
- 主题、品牌、多语言。
- 审批任务、流程定义、集成配置。
- Kanban、大屏管理、设计器入口页。

## 2. 设计原则

IAF 平台管理端是高频企业后台，不做营销式页面。

原则：

- 信息密度高，但层级清楚。
- 默认视图安静克制，重点动作突出。
- 标准页面统一，复杂页面保留专业工具感。
- 页面操作必须可预测，避免同一类动作在不同页面使用不同交互。
- 所有按钮、字段、菜单、动作必须同时受权限、状态、字段权限和 view mode 控制。

## 3. 页面骨架

平台管理页面统一使用：

```text
页面标题区
查询 / 筛选区
工具栏
主体区
辅助信息区，按需
```

页面标题区包含：

- 页面标题。
- 面包屑或模块路径，复杂模块启用。
- 页面级主操作。
- 帮助入口和 AI 助手入口，按需。

主体区按页面类型变化：

- 列表页：表格或树表。
- 表单页：分组表单。
- 详情页：摘要、详情块、关联数据、时间线。
- 设计器页：画布、组件栏、属性面板。
- Kanban 页：列和卡片。
- 大屏页：全屏画布。

## 4. 标准列表页

列表页用于查询、筛选、批量处理和进入详情。

布局：

```text
标题区
查询区
工具栏：新增 / 导入 / 导出 / 批量操作 / 列设置 / 视图保存
表格
分页
```

查询区规则：

- 默认显示 3 到 5 个高频条件。
- 低频条件进入“高级筛选”。
- 查询条件必须支持重置。
- 常用查询组合必须支持保存为视图。
- 查询按钮放左侧或查询区末尾，重置按钮紧邻查询按钮。

表格规则：

- 默认紧凑密度。
- 支持列显示/隐藏。
- 支持列顺序。
- 支持列宽。
- 支持固定列。
- 操作列固定在右侧。
- 主标识字段可点击进入详情。
- 状态字段必须使用统一状态组件。

操作列规则：

- 高频操作最多直接展示 3 个。
- 低频操作进入“更多”。
- 危险操作必须二次确认。
- 禁用/启用/删除/作废必须说明影响。
- 无权限操作不展示。
- 因状态不可操作时可展示 disabled，并提供 tooltip 说明。

## 5. 新增与编辑

新增/编辑支持三种操作模式，最终展示方式可由页面元数据、主题能力和用户偏好共同决定：

| 模式 | 适用场景 | 默认尺寸 |
|---|---|---|
| Modal | 字段少于 8 个、无复杂关联、提交即返回列表 | 标准 680px，简单确认 520px，复杂向导 840px |
| Drawer | 字段 8 到 20 个、需要保留列表上下文、需要查看辅助信息 | 标准 640px，配置型 720px，宽表单 880px |
| 独立页面 | 字段多、分组多、有明细行、涉及审批/状态/附件/日志 | 占用页面内容区，隐藏列表主体 |

配置来源优先级：

1. 页面或业务对象强约束，例如流程设计器、大屏编辑器必须使用独立页面。
2. 管理员配置的页面元数据，例如某类主数据统一使用 Drawer。
3. 主题或体验模式默认值，例如 `light-industrial` 默认 Drawer，`compact` 默认 Modal。
4. 用户个人偏好，例如同一标准对象可选择 Modal 或 Drawer。

规则：

- 用户、角色、字典项等简单对象默认可使用 Modal，也必须允许通过配置切换到 Drawer。
- 菜单、主题、集成配置默认优先使用 Drawer。
- 流程、大屏、复杂审批配置必须使用独立页面或设计器。
- Modal 宽度不得低于 520px；普通新增/编辑不得使用窄小弹窗，避免企业表单拥挤。
- Drawer 宽度不得低于 560px；标准管理表单推荐 640px 到 720px，复杂配置推荐 880px 到 960px。
- Drawer 应支持宽度档位配置；复杂低代码表单可支持拖拽调整宽度，并将用户偏好持久化。
- Drawer 和 Modal 必须使用统一标题区、内容区、底部操作区；保存、取消、危险动作位置必须一致。
- Drawer 底部操作区应固定在底部，滚动只发生在表单内容区。
- Modal 只承载短流程；多步骤、明细行、权限树、流程节点、主题编辑等不得塞进窄弹窗。
- 使用独立页面模式时，列表视图必须退出可见主体区；不得在列表下方或列表旁边直接堆叠新增/编辑表单。
- 独立页面模式必须提供返回、保存、保存并返回、取消和 dirty state 离开提示。
- 独立页面保存成功后返回列表时，必须恢复原查询条件、分页、排序、列设置和选中上下文。
- 页面模式、Drawer 模式、Modal 模式必须由统一 FormInteractionSurface 或等价共享组件承载，业务页面不得重复实现三套交互。
- 表单必须支持 loading、保存中、提交失败。
- 离开有未保存内容的页面必须提示。
- 保存成功后，列表刷新并保留查询上下文。
- 不允许同一类标准对象在不同页面硬编码不同交互模式；必须经页面元数据或用户偏好决定。

响应式规则：

- 小于 768px 时，Modal 和 Drawer 自动降级为全屏表单页。
- 768px 到 1200px 时，Drawer 最大宽度不超过视口 88%，Modal 最大宽度不超过视口 86%。
- 大于 1200px 时，Drawer 可使用 720px 到 960px；设计器和复杂表单优先独立页面。

视觉规则：

- 标题必须包含动作语义和对象名称，例如“新建用户”“编辑角色”“菜单详情”。
- 只读详情、编辑、创建必须有明显模式差异，不能只靠按钮文案区分。
- 表单分组用轻量分割标题或 Tabs，不使用卡片套卡片。
- 错误提示必须显示在字段附近；全局错误放在表单顶部。

## 6. 查看详情

详情页用于展示对象完整上下文和可执行动作。

推荐结构：

```text
摘要区：名称、编码、状态、关键属性
操作区：主动作、次动作、危险动作、更多
详情 Tab：
  基本信息
  关联数据
  权限/配置
  审批记录
  操作日志
  附件
```

规则：

- 详情页默认只读。
- 编辑动作进入 Drawer 或独立编辑页。
- 状态变化必须记录时间线。
- 审批类对象必须展示审批时间线。
- 配置类对象必须展示版本或变更记录。

## 7. 树和树表页面

适用于组织、菜单、分类、部门、流程节点等层级对象。

布局：

```text
左侧树
右侧详情 / 列表 / 表单
```

规则：

- 左树宽度默认 280px，可调整。
- 树节点支持搜索。
- 树节点右键或更多菜单提供新增子级、编辑、禁用。
- 右侧显示当前节点详情和子级列表。
- 拖拽排序必须二次确认或支持撤销。

## 8. 危险操作

危险操作包括：

- 删除。
- 禁用。
- 作废。
- 取消发布。
- 重置密码。
- 清空配置。
- 强制同步。

规则：

- 必须二次确认。
- 必须显示影响范围。
- 高风险操作要求输入对象编码确认，按任务需要启用。
- 后端必须再次校验权限和状态。

## 9. 空态、错误态、加载态

空态：

- 首次空数据：说明对象用途，并展示创建入口。
- 查询无结果：提示调整筛选条件。
- 无权限空态：提示无权限，不展示创建入口。

错误态：

- 业务错误显示业务文案和错误码。
- 系统错误显示错误码和追踪 ID。
- 网络错误提供重试按钮。

加载态：

- 列表用 skeleton 或表格 loading。
- 表单保存用按钮 loading。
- 长任务用进度或任务日志。

## 10. 简洁模式与专家模式

平台页面必须预留 view mode：

- 简洁模式：保留高频字段和主要动作。
- 专家模式：展示高级字段、批量操作、配置入口和调试信息。

规则：

- 不允许复制两套页面。
- table-engine 和 form-engine 必须支持 view mode 过滤。
- 管理员默认专家模式。
- 普通业务用户默认简洁模式。

## 11. 当前决策记录

已采纳：

- 平台页面优先使用高密度企业后台布局。
- 标准列表使用 table-engine。
- 标准表单使用 form-engine。
- 新增/编辑支持 Modal、Drawer、独立页面三种模式，并通过页面元数据、主题能力和用户偏好配置。
- 简单对象默认 Modal，复杂配置默认 Drawer，设计器强制独立页面。
- Modal、Drawer、独立页面必须使用统一交互承载面，尺寸、底部操作、dirty state 和保存后返回行为由规范统一。
- 独立页面新增/编辑时必须隐藏列表主体，只保留导航返回与上下文恢复能力。
- 详情页采用摘要 + 操作区 + Tab 结构。

暂不采用：

- 营销式大卡片页面作为管理端默认页面。
- 每个页面自定义操作布局。
- 复制页面实现简洁/专家模式。
- 由单个页面组件硬编码新增/编辑展示方式。

## 12. 平台管理页面交付 Checklist

后续新增或改造平台管理页面时，必须按以下清单自检：

- 文案：所有用户可见文字使用 i18n key，页面内不硬编码中文或英文业务文案。
- 主题：颜色、间距、圆角、状态色使用 Ant Design token 或 `@iaf/theme` 语义 token，页面内不直接写状态颜色。
- 权限：路由使用 `PermissionRoute`，按钮使用 `PermissionButton` 或 `PermissionGate`，页面不得直接写 `permissions.includes(...)`。
- 字段权限：字段可见、只读、隐藏、脱敏通过 `FieldPermissionWrapper` 或等价统一封装处理。
- API：所有 HTTP 调用通过 `packages/api-client`，页面调用模块 `hooks.ts`，不直接拼 URL。
- 状态：列表、表单、详情必须提供 loading、error、empty、permission denied 的可理解状态。
- 表单：必填、格式、提交中、提交失败、取消和 dirty state 行为明确。
- 批量操作：列表批量操作必须同时考虑权限、业务状态和字段权限；危险操作必须二次确认。
- 表格：标准列表优先使用 `table-engine`，并支持列偏好、查询重置和刷新。
- 响应式：小屏下 Modal/Drawer 降级为全屏可用视图，不出现水平溢出。
- 键盘：搜索、菜单、主要操作入口支持键盘可达；图标按钮必须有可访问名称。
- Token：页面不得直接读写认证 token 或处理刷新逻辑。
- 测试：新增或改造页面至少覆盖主流程、权限隐藏、loading/error/empty 中的关键状态。
- Code map：新增路由、API、权限点、公共组件或数据库对象时同步 `docs/code-map/*`。
