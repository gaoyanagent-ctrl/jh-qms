# 测试方法和标准

## 1. 测试分层

IAF 平台需要采用分层测试策略。不能只依赖人工点击，也不能只写单元测试。

| 层级 | 目标 | 工具建议 | 必测对象 |
|---|---|---|---|
| Unit Test | 验证领域规则和纯函数 | JUnit 5、Mockito、Vitest | 状态机、规则、编码、策略、权限判断 |
| Integration Test | 验证 Spring Bean、事务、数据库、Mapper | Spring Boot Test、Testcontainers | Application Service、Repository、Migration |
| API Test | 验证接口契约、鉴权、数据权限 | REST Assured、OpenAPI 校验 | Controller、权限、错误码 |
| Contract Test | 验证前后端契约一致 | OpenAPI diff、生成类型检查 | DTO、枚举、分页、错误结构 |
| Frontend Component Test | 验证页面组件行为 | Vitest、React Testing Library | 表单、列表、权限按钮、设计器组件 |
| E2E Test | 验证关键业务闭环 | Playwright | 登录、收货、上架、审批、库存查询 |
| Migration Test | 验证数据库升级可执行 | Flyway + Testcontainers | migration 顺序、索引、约束 |
| Security Test | 验证越权和隔离 | API test + 自定义用例 | 多组织、供应商门户、字段权限 |

## 2. 覆盖率标准

第一阶段建议标准：

| 模块类型 | 行覆盖率 | 分支覆盖率 | 说明 |
|---|---:|---:|---|
| shared/platform core | >= 80% | >= 70% | 基础能力必须稳定 |
| 状态机/规则/权限/审批适配 | >= 85% | >= 75% | 高风险模块 |
| WMS 库存事务/上架策略 | >= 85% | >= 75% | 库存错误成本高 |
| 普通 CRUD | >= 60% | >= 40% | 可用 API/集成测试补充 |
| 前端组件 | 关键组件必须有测试 | - | 不强行追求全量覆盖 |

## 3. 必测业务场景

### 权限

- 未登录访问被拒绝。
- 无菜单权限不可见菜单。
- 无按钮权限不可执行动作。
- 无 API 权限直接调用接口被拒绝。
- 数据权限限制本工厂、本仓库、本供应商数据。
- 字段权限隐藏或只读敏感字段。

### 审批

- 提交后生成审批实例和任务。
- 不同审批人解析规则正确。
- 同意、拒绝、退回、撤回状态正确。
- 审批节点字段权限生效。
- 审批通过后业务状态映射正确。

### 状态机

- 合法状态迁移成功。
- 非法状态迁移被拒绝。
- 状态迁移记录审计日志。
- 并发状态变更通过 version 控制。

### WMS 库存

- 收货确认生成待上架库存或上架任务。
- 上架确认增加库存余额。
- 每次库存变化必须写库存事务。
- 重复过账被拒绝。
- 批次、序列号、库位维度一致。
- 库存余额不能出现非法负数，除非业务规则明确允许。

## 4. CI 测试命令建议

```bash
# Backend
cd backend
./mvnw clean verify

# Frontend
cd frontend
pnpm install --frozen-lockfile
pnpm typecheck
pnpm lint
pnpm test
pnpm build

# E2E
cd tests/e2e
pnpm test
```

## 5. Definition of Done

一个任务只有满足以下条件才能认为完成：

1. 代码编译通过。
2. 相关测试通过。
3. 新增或变更的业务逻辑有测试覆盖。
4. 数据库 migration 可从空库执行成功。
5. 权限点已定义并生效。
6. API 文档或 OpenAPI 类型同步。
7. 没有绕过状态机、审批、数据权限、审计和 Outbox 的实现。
8. AI 输出了最终变更说明和风险说明。
