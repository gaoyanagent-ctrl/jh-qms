# 质量门禁和 CI 规范

## 1. 分支策略

建议：

```text
main              # 可发布分支
release/*         # 发布准备分支
feature/*         # 功能分支
bugfix/*          # 缺陷修复分支
experiment/*      # AI 探索分支，不允许直接合并 main
```

AI 大规模改动必须使用 feature 或 experiment 分支。

## 2. 提交规范

使用 Conventional Commits：

```text
feat(wms): add receipt order posting flow
fix(permission): apply plant data scope to warehouse query
refactor(platform): split approval adapter from workflow service
test(wms): add inventory posting integration tests
docs(ai): add codex task template
```

## 3. Pull Request 标准

PR 必须包含：

- 变更摘要。
- 关联任务。
- 影响模块。
- 数据库 migration 说明。
- 权限点说明。
- 测试结果。
- 风险和回滚方案。

## 4. CI Pipeline

```text
1. Checkout
2. Backend format check
3. Backend compile
4. Backend unit tests
5. Backend integration tests
6. Flyway migration test
7. Frontend install
8. Frontend typecheck
9. Frontend lint
10. Frontend unit tests
11. Frontend build
12. E2E smoke tests
13. Security scan
14. Dependency scan
15. Build docker image
```

## 5. 质量门禁

| 门禁 | 标准 |
|---|---|
| 编译 | 必须通过 |
| 后端单元测试 | 必须通过 |
| 后端集成测试 | 核心模块必须通过 |
| 前端 typecheck | 必须通过 |
| 前端 lint | 必须通过 |
| Migration test | 必须通过 |
| 安全扫描 | 不允许高危漏洞 |
| 许可证扫描 | 不允许不可商用许可证 |
| 覆盖率 | 不低于模块标准 |
| 架构检查 | 不允许非法模块依赖 |

## 6. AI 自动修复规则

Codex 可以自动修复：

- 编译错误。
- 类型错误。
- lint 错误。
- 测试失败中的明确断言错误。
- 缺少 import、命名不一致、DTO 字段同步问题。

Codex 不允许自动决定：

- 删除测试以通过 CI。
- 放宽权限以通过测试。
- 移除业务校验以通过流程。
- 修改 migration 历史文件。
- 大幅改变架构边界。
