# 代码质量审核规范

## 1. 审核目标

代码审核不仅检查代码是否能运行，更要检查：

- 是否符合 IAF 架构边界。
- 是否符合制造业务范式。
- 是否存在权限、租户、多组织、审计缺失。
- 是否引入未来难以维护的技术债。
- 是否破坏 AI coding 后续可读性和可生成性。

## 2. 审核清单

### 架构

- Controller 是否只负责 HTTP 入参、出参、鉴权入口。
- Application Service 是否负责编排事务和用例。
- Domain Service 是否承载核心业务规则。
- Infrastructure 是否封装数据库、外部接口、Flowable、文件存储等技术细节。
- 平台模块是否被场景模块反向依赖。
- shared 是否被滥用为业务垃圾桶。

### 数据库

- 新表是否有 tenant_id、审计字段、deleted、version、ext_json。
- 单据表是否有 document_no、document_status、approval_status 等标准字段。
- 是否添加必要索引。
- 是否修改历史 migration。
- 是否存在无约束的大文本、JSON 滥用、缺少唯一约束的编码字段。

### 权限与安全

- 新接口是否有鉴权和权限点。
- 数据查询是否应用数据权限。
- 外部用户是否只能访问自己的供应商/客户数据。
- 字段权限是否在后端也生效，不能只靠前端隐藏。
- 是否存在 SQL 注入、表达式注入、文件上传风险。

### 业务一致性

- 状态变更是否通过状态机。
- 审批流是否通过 Approval Service。
- 库存变化是否写库存事务。
- 外部调用是否通过集成中心或 Outbox。
- 异常是否有业务错误码和可读信息。

### 前端

- 页面是否使用统一布局、ProTable、ProForm 和权限组件。
- 是否硬编码枚举、状态、权限、URL。
- 是否处理 loading、empty、error、权限不可见状态。
- 是否复用通用组件，而不是复制粘贴。

### 测试

- 关键领域逻辑是否有单元测试。
- 数据库和事务逻辑是否有集成测试。
- 权限和越权是否有测试。
- bug 修复是否有回归测试。

## 4. 阻断级问题

出现以下问题必须阻断合并：

1. 新接口无鉴权或无权限点。
2. 数据权限、租户隔离、多组织隔离缺失。
3. 库存余额更新没有库存事务。
4. 审批和状态绕过平台服务直接改字段。
5. migration 不可重复执行或修改历史 migration。
6. 测试无法运行且没有合理说明。
7. 引入明文密码、token、密钥或敏感配置。
8. 破坏模块边界，造成平台模块依赖业务场景模块。
