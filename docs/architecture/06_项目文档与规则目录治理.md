# 项目文档与规则目录治理

## 1. 目的

本文件定义 IAF 仓库内规则、规格、任务、交接计划、代码地图和原始资料的职责边界，避免多个目录同时成为“规则源”或“任务源”。

所有 Agent 必须按本文件判断文档权威级别。

## 2. 权威级别

当文档内容冲突时，按以下优先级处理：

1. `AGENTS.md`
2. `docs/decisions/*.md`
3. `ai-coding/rules/*.md`
4. 当前任务文件 `ai-coding/tasks/**/*.md`
5. `docs/module-specs/**/*.md`
6. `docs/frontend/*.md`、`docs/architecture/*.md`
7. `docs/code-map/*.md`
8. `docs/operations/*.md`
9. 原始资料归档目录，如 `docs/codex_rules/`、`docs/iaf_frontend_specs/`

若低优先级文档与高优先级文档冲突，以高优先级为准，并在最终报告中说明冲突。

## 3. 目录职责

### `AGENTS.md`

项目总入口和全局规则索引。

用于：

- 定义项目定位。
- 定义必读顺序。
- 定义不可违反的工程规则。
- 指向规则、任务、规格、质量门禁和代码地图。

禁止：

- 放具体任务实施细节。
- 复制大量模块规格。

### `ai-coding/rules/`

唯一可执行规则目录。

用于：

- 存放 Agent 必须遵守的工程规则。
- 按关注点拆分后端、前端、数据库、API、权限、测试、代码地图等规则。
- 提供短、明确、可检查的约束。

禁止：

- 放产品说明、长篇背景材料或历史讨论。
- 放具体任务计划。
- 与 `docs/frontend/`、`docs/module-specs/` 形成两套同级规则。

### `ai-coding/tasks/`

唯一正式任务规格目录。

用于：

- 存放可执行开发任务。
- 存放任务模板。
- 按阶段或能力域组织任务。

任务文件应包含：

- 目标。
- 必读文档。
- 范围内和范围外。
- 需要改动的模块和文件类型。
- API、数据库、权限、测试、代码地图要求。
- 验收标准。

禁止：

- 把临时 handoff 计划当成正式任务。
- 在 `docs/` 下维护第二套正式任务库。

### `docs/architecture/`

架构规格和长期工程决策背景。

用于：

- 总体架构。
- 技术选型。
- 平台模块设计。
- 样板场景设计。
- 文档和规则治理。

禁止：

- 放一次性执行计划。
- 放已分派给 Agent 的具体任务清单。

### `docs/module-specs/`

模块规格目录。

用于：

- 说明模块业务边界。
- 定义领域模型、用例、状态、接口预期和业务约束。

禁止：

- 代替 `ai-coding/tasks/` 成为任务源。
- 记录临时执行过程。

### `docs/frontend/`

前端规格目录。

用于：

- 前端总体架构。
- PC 和移动端体验规范。
- 组件体系。
- 主题、i18n、权限、状态、低代码配置、AI 助手等规格。
- 前端路线图或任务拆分总览。

重要约定：

- `ai-coding/rules/03_frontend_rules.md` 是前端可执行规则源。
- `docs/frontend/14_Codex前端开发规则.md` 只能作为前端规格包中的规则索引，不得覆盖 `ai-coding/rules/03_frontend_rules.md`。
- `docs/frontend/15_前端任务拆分清单.md` 是路线图和拆分总览，不是执行任务源。
- 具体前端任务必须落到 `ai-coding/tasks/frontend/`。

禁止：

- 在这里维护和 `ai-coding/tasks/frontend/` 并行的正式任务文件。
- 在这里定义与 `ai-coding/rules/03_frontend_rules.md` 冲突的可执行规则。

### `docs/code-map/`

当前代码地图目录。

用于：

- 描述当前代码、模块、类、方法、API、数据库对象、前端路由和跨模块依赖。
- 帮助 Agent 快速理解当前实现。

更新要求：

- 改代码、API、数据库、前端路由、公共方法、跨模块依赖时，同任务更新代码地图。
- 不要复制源码细节，只记录导航和语义。

禁止：

- 放计划、需求、未实现设计。
- 用代码地图替代任务验收标准。

### `docs/operations/`

操作、交接和运行记录目录。

用于：

- 下一位 Agent 的 handoff plan。
- 一次性执行计划。
- 本地开发环境运行说明。
- 故障排查记录。
- 部署或运维 runbook。

命名规则：

- `HANDOFF-*.md`：交接计划。
- `RUNBOOK-*.md`：运行手册。
- `INCIDENT-*.md`：问题排查或事故记录。
- `NOTE-*.md`：环境或操作备注。

禁止：

- 使用 `TASK-*.md` 命名，避免和 `ai-coding/tasks/` 混淆。
- 作为正式任务源。

### 原始资料归档目录

包括：

- `docs/codex_rules/`
- `docs/iaf_frontend_specs/`
- `docs/IAF平台Codex可执行开发规格包_v1.0_markdown/`

用于：

- 保留原始输入资料。
- 做历史追溯。
- 必要时为新规范提供参考。

禁止：

- 直接作为当前执行规则源。
- 直接作为当前任务源。

## 4. 新文档放置规则

新增文档前先判断类型：

| 文档类型 | 放置位置 |
|---|---|
| 可执行规则 | `ai-coding/rules/` |
| 正式开发任务 | `ai-coding/tasks/` |
| 架构设计 | `docs/architecture/` |
| ADR | `docs/decisions/` |
| 模块业务规格 | `docs/module-specs/` |
| 前端体验或工程规格 | `docs/frontend/` |
| 代码地图 | `docs/code-map/` |
| 交接计划 | `docs/operations/HANDOFF-*.md` |
| 运行手册 | `docs/operations/RUNBOOK-*.md` |
| 故障排查记录 | `docs/operations/INCIDENT-*.md` |

## 5. Agent 执行判断

Agent 开始任务时：

1. 先读 `AGENTS.md`。
2. 再读本治理文档。
3. 再读相关 `ai-coding/rules/*`。
4. 如果用户指定了任务文件，确认它位于 `ai-coding/tasks/`；如果位于 `docs/operations/`，按 handoff plan 对待。
5. 如果发现两个文件都像任务源，以 `ai-coding/tasks/` 为准。
6. 如果发现两个文件都像规则源，以 `ai-coding/rules/` 为准。
7. 如果需要保留执行计划，放到 `docs/operations/HANDOFF-*.md`。

## 6. 维护要求

- 更新目录职责时，必须同步更新 `AGENTS.md`。
- 新增正式任务时，必须放到 `ai-coding/tasks/`。
- 新增 handoff 时，必须放到 `docs/operations/` 并使用非 `TASK-*` 命名。
- 规格包归档目录不得被编辑成当前执行源；需要吸收内容时，复制或整理到当前规范目录。
