# 移动端作业与扫码规范

## 1. 移动端定位

移动端服务于现场作业人员，第一版优先 WMS，覆盖手机 H5、PDA、蓝牙扫码枪、企微、钉钉、飞书内嵌环境。

## 2. 移动端首页

底部导航建议：

```text
任务 | 扫码 | 库存 | 消息 | 我的
```

## 3. WMS 第一版移动页面

- 收货任务列表
- 扫码收货
- 收货确认
- 上架任务列表
- 扫码上架
- 库位查询
- 库存查询
- 异常上报
- 离线任务

## 4. 移动作业设计原则

- 一屏只做一个核心动作。
- 扫码优先，手工输入兜底。
- 主按钮高度不低于 44px。
- 扫码反馈必须即时明确。
- 成功、失败、异常必须有明显反馈。
- 作业完成必须二次确认。
- 异常上报入口固定可见。

## 5. 扫码运行时

统一包：

```text
packages/scan-runtime/
  ScanService
  ScanDeviceAdapter
  CameraScanAdapter
  KeyboardScanAdapter
  BluetoothScanAdapter
  PdaNativeScanAdapter
  WeComScanAdapter
  DingTalkScanAdapter
  FeishuScanAdapter
  ScanParser
  ScanActionRouter
```

## 6. 扫码结果模型

```ts
type ScanResult = {
  rawText: string;
  source: 'camera' | 'pda' | 'bluetooth' | 'wecom' | 'dingtalk' | 'feishu' | 'manual';
  parsedType?: 'MATERIAL' | 'LOCATION' | 'TASK' | 'ORDER' | 'PACKAGE' | 'BATCH' | 'SERIAL';
  parsedValue?: string;
  scannedAt: string;
};
```

## 7. 扫码流程

```text
扫描输入
  -> ScanParser 解析条码类型
  -> ScanActionRouter 匹配当前作业场景
  -> 调用业务作业 Hook
  -> 显示操作结果
  -> 写入在线或离线队列
```

## 8. PDA 与蓝牙扫码枪

PDA 和蓝牙扫码枪通常以键盘输入方式注入扫码结果。必须提供 `KeyboardScanAdapter`，通过输入间隔和结束符识别扫码结果，不允许在页面中自行监听键盘流。

## 9. 企业微信 / 钉钉 / 飞书

扫码能力通过适配器封装，不允许业务页面直接调用平台 JS SDK。


## Codex 执行要求

- 开始实现前必须读取 `AGENTS.md`、`ai-coding/rules/frontend-rules.md` 和本规范。
- 不允许绕过 `packages/api-client` 直接调用 HTTP。
- 不允许在页面中硬编码中文、颜色、权限判断、状态判断。
- 新增页面必须同时补齐类型定义、API hooks、i18n key、权限点、基础测试和 Story/示例数据。
- 复杂页面必须输出 `PageAIContext`，供 AI 助手解释页面状态和下一步动作。
