# PC 多标签页与工作台规范

## 1. 多标签页目标

IAF PC 端需要支持 ERP 风格的多任务工作方式，允许用户同时打开多个单据、列表、配置页和审批任务。

## 2. 核心能力

必须实现：

- 打开路由即创建 Tab
- 同一列表页只打开一个 Tab
- 不同单据详情可打开多个 Tab
- Tab 刷新
- 关闭当前 / 关闭其他 / 关闭右侧
- 固定 Tab
- 最近访问
- 表单未保存关闭提醒
- 恢复上次工作区

## 3. 核心组件

```text
TabWorkspace
RouteTabStore
KeepAliveRoute
DirtyStateRegistry
RecentlyVisitedStore
PinnedTabManager
```

## 4. Dirty State 规则

所有编辑页必须注册未保存状态：

```ts
useDirtyState({
  tabId,
  dirty: form.isFieldsTouched(),
  messageKey: 'common.message.unsavedChanges'
});
```

未经确认不得关闭含未保存数据的 Tab。

## 5. 工作台首页

工作台是用户进入系统后的第一屏，必须支持：

- 我的待办
- 我的任务
- 业务快捷入口
- 异常预警
- 常用报表
- 最近访问
- 收藏菜单
- AI 助手入口

## 6. 制造业务工作台卡片

第一版建议卡片：

| 卡片 | 内容 |
|---|---|
| 待审批 | 当前用户审批任务 |
| 待收货 | WMS 待收货任务 |
| 待上架 | WMS 待上架任务 |
| 库存异常 | 负库存、冻结、超期 |
| 今日收货 | 今日收货数量、单据数 |
| 我的常用 | 用户收藏菜单 |
| 最近访问 | 最近打开页面或单据 |

## 7. 工作台配置

第一版支持用户：

- 隐藏卡片
- 调整卡片顺序
- 选择简洁 / 专家模式

第二阶段支持角色默认工作台和拖拽配置。

## 8. Codex 规则

- 所有路由页面必须接入 `TabWorkspace`。
- 业务页面不得自己实现 Tab 状态。
- 编辑页必须注册 `DirtyStateRegistry`。
- 工作台卡片必须通过统一 `WorkbenchCard` 组件实现。


## Codex 执行要求

- 开始实现前必须读取 `AGENTS.md`、`ai-coding/rules/frontend-rules.md` 和本规范。
- 不允许绕过 `packages/api-client` 直接调用 HTTP。
- 不允许在页面中硬编码中文、颜色、权限判断、状态判断。
- 新增页面必须同时补齐类型定义、API hooks、i18n key、权限点、基础测试和 Story/示例数据。
- 复杂页面必须输出 `PageAIContext`，供 AI 助手解释页面状态和下一步动作。
