# 移动端离线能力规范

## 1. 离线能力定位

第一版需要支持移动端 WMS 作业在弱网或短时无网情况下继续执行部分任务。离线能力不是全系统离线，而是任务包离线和操作队列离线。

## 2. 第一版离线范围

支持：

- 收货任务缓存
- 上架任务缓存
- 物料基础信息缓存
- 库位基础信息缓存
- 扫码记录缓存
- 收货确认离线排队
- 上架确认离线排队

不支持：

- 离线审批
- 离线库存调整
- 离线复杂盘点
- 离线跨单据联动
- 离线规则配置修改

## 3. offline-runtime 包

```text
packages/offline-runtime/
  OfflineStore
  OfflineTaskPackage
  OfflineMutationQueue
  SyncService
  ConflictResolver
  NetworkStatus
  OfflineAuditLog
```

## 4. 离线数据模型

```ts
type OfflineTaskPackage = {
  packageId: string;
  userId: string;
  module: 'wms';
  taskType: 'receipt' | 'putaway';
  downloadedAt: string;
  expiresAt: string;
  data: unknown;
};

type OfflineMutation = {
  id: string;
  operationType: string;
  payload: unknown;
  status: 'PENDING' | 'SYNCING' | 'SUCCESS' | 'FAILED' | 'CONFLICT';
  createdAt: string;
  lastError?: string;
};
```

## 5. 同步流程

```text
网络恢复
  -> SyncService 扫描 PENDING 操作
  -> 按创建顺序提交
  -> 后端幂等校验
  -> 成功后标记 SUCCESS
  -> 冲突则标记 CONFLICT 并提示人工处理
```

## 6. 幂等要求

所有移动端离线提交必须带：

```text
clientOperationId
clientDeviceId
clientSubmittedAt
```

后端必须保证重复提交不会产生重复库存事务。

## 7. 用户提示

移动端必须清晰显示：

- 当前网络状态
- 当前离线任务数量
- 待同步数量
- 同步失败数量
- 冲突任务入口


## Codex 执行要求

- 开始实现前必须读取 `AGENTS.md`、`ai-coding/rules/frontend-rules.md` 和本规范。
- 不允许绕过 `packages/api-client` 直接调用 HTTP。
- 不允许在页面中硬编码中文、颜色、权限判断、状态判断。
- 新增页面必须同时补齐类型定义、API hooks、i18n key、权限点、基础测试和 Story/示例数据。
- 复杂页面必须输出 `PageAIContext`，供 AI 助手解释页面状态和下一步动作。
