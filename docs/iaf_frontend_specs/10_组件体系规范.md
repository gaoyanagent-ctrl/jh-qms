# 组件体系规范

## 1. 组件分层

```text
ui-core          纯 UI 和布局组件
ui-business      通用业务组件
module-components 模块内组件
page-components  页面组合组件
```

## 2. ui-core 组件

必须优先提供：

- PageContainer
- SearchPanel
- ActionBar
- DataTable
- EditableLineTable
- DetailDescriptions
- StatusTag
- ConfirmActionButton
- EmptyState
- ErrorState
- LoadingState

## 3. ui-business 组件

- OrgSelector
- PlantSelector
- WarehouseSelector
- LocationSelector
- MaterialSelector
- SupplierSelector
- CustomerSelector
- UserSelector
- RoleSelector
- ApprovalTimeline
- AuditTimeline
- AttachmentPanel
- BusinessActionBar
- StateTransitionButton

## 4. WMS 业务组件

- MaterialBarcodeInput
- LocationBarcodeInput
- InventoryStatusTag
- BatchNoInput
- SerialNoListInput
- QuantityInput
- WarehouseLocationTree
- PutawaySuggestionPanel
- InventoryBalanceCard

## 5. 组件 API 要求

所有公共组件必须满足：

- TypeScript 类型完整
- 支持 i18n
- 支持 theme token
- 支持 disabled / readonly
- 支持 loading
- 支持 test id
- 不直接调用业务 API，除非是明确的 selector 组件

## 6. 禁止重复造组件

Codex 生成页面时，必须先检查是否存在可复用组件。禁止在业务页面中重复实现物料选择、供应商选择、仓库选择、库位树、状态标签、审批时间线等组件。


## Codex 执行要求

- 开始实现前必须读取 `AGENTS.md`、`ai-coding/rules/frontend-rules.md` 和本规范。
- 不允许绕过 `packages/api-client` 直接调用 HTTP。
- 不允许在页面中硬编码中文、颜色、权限判断、状态判断。
- 新增页面必须同时补齐类型定义、API hooks、i18n key、权限点、基础测试和 Story/示例数据。
- 复杂页面必须输出 `PageAIContext`，供 AI 助手解释页面状态和下一步动作。
