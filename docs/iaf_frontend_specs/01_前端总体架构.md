# IAF 前端总体架构

## 1. 定位

IAF 前端是面向制造企业管理应用的统一前端应用框架，覆盖 PC 管理、PC 业务作业、移动现场作业、大屏看板、供应商门户和配置设计器。

## 2. 技术栈

| 能力 | 选型 |
|---|---|
| 包管理 | pnpm workspace |
| 构建 | Vite |
| 主框架 | React + TypeScript |
| PC UI | Ant Design + ProComponents |
| 移动 UI | Ant Design Mobile |
| 路由 | React Router |
| 服务端状态 | TanStack Query |
| 全局 UI 状态 | Zustand |
| 图表 | ECharts |
| 国际化 | i18next |
| 离线存储 | IndexedDB + Dexie |
| PWA | Workbox / Vite PWA |
| 原生能力桥接 | Capacitor 预留 |

## 3. 应用分层

```text
frontend/
  apps/
    pc-admin/          # PC 管理端 + PC 业务作业端
    mobile-work/       # 手机 H5 / PDA 作业端
    dashboard-view/    # 大屏看板端，第二阶段
    supplier-portal/   # 供应商门户，第二阶段

  packages/
    api-client/
    auth/
    permissions/
    i18n/
    theme/

    ui-business/
    table-engine/
    form-engine/
    lowcode-engine/
    scan-runtime/
    offline-runtime/
    ai-assistant/
```

## 4. 应用边界

### pc-admin

包含系统管理、基础资料、业务单据、审批、报表、配置设计器、工作台、多标签页和 AI 助手。

### mobile-work

包含 WMS 优先的现场作业能力：收货、上架、库存查询、库位查询、扫码、离线任务、异常上报。

### dashboard-view

大屏展示端，使用独立主题和布局，第一版预留。

### supplier-portal

供应商门户端，使用独立权限域和外部用户身份，第一版预留。

## 5. 依赖方向

```text
apps -> packages
packages/ui-business -> packages/ui-core
packages/table-engine -> api-client + permissions + theme + i18n
packages/form-engine -> permissions + theme + i18n
packages/ai-assistant -> domain-types + permissions
packages 不允许依赖 apps
```

## Codex 执行要求

- 开始实现前必须读取 `AGENTS.md`、`ai-coding/rules/frontend-rules.md` 和本规范。
- 不允许绕过 `packages/api-client` 直接调用 HTTP。
- 不允许在页面中硬编码中文、颜色、权限判断、状态判断。
- 新增页面必须同时补齐类型定义、API hooks、i18n key、权限点、基础测试和 Story/示例数据。
- 复杂页面必须输出 `PageAIContext`，供 AI 助手解释页面状态和下一步动作。
