# 多主题设计规范

## 1. 目标

IAF 必须支持客户品牌化、浅色、暗黑、紧凑、大屏、移动作业、高对比主题和项目级主题包。

## 2. 主题类型

| 主题 | 用途 |
|---|---|
| light | 默认 PC 主题 |
| dark | 暗黑模式 |
| compact | 高密度数据录入和查询 |
| dashboard | 大屏看板 |
| mobile-work | 移动作业 |
| high-contrast | 高对比辅助 |
| customer-brand | 客户品牌主题 |

## 3. ThemeDefinition

```ts
type ThemeDefinition = {
  id: string;
  name: string;
  mode: 'light' | 'dark' | 'compact' | 'dashboard' | 'mobile' | 'high-contrast';
  logoUrl?: string;
  brandName?: string;
  tokens: {
    colorPrimary: string;
    colorSuccess: string;
    colorWarning: string;
    colorError: string;
    colorInfo: string;
    borderRadius: number;
    fontSizeBase: number;
    spacingBase: number;
  };
  semanticTokens: {
    statusDraft: string;
    statusPending: string;
    statusApproved: string;
    statusRejected: string;
    inventoryAvailable: string;
    inventoryFrozen: string;
    taskUrgent: string;
  };
};
```

## 4. Token 分层

```text
Global Token      基础颜色、字体、间距、圆角
Semantic Token    业务语义颜色，例如审批、库存、任务
Component Token   表格、表单、菜单、卡片、移动按钮
```

## 5. 状态颜色规范

状态展示必须使用 `StatusTag` 或业务状态组件，不能直接指定颜色。

| 语义 | 用途 |
|---|---|
| neutral | 草稿、关闭 |
| processing | 执行中 |
| warning | 待审批、库存冻结 |
| success | 已完成、已通过、可用库存 |
| error | 已拒绝、异常、失败 |

## 6. 客户品牌配置

客户可以配置：

- Logo
- 品牌名
- 主色
- 登录页背景
- favicon
- 默认主题

这些配置必须来自后端主题配置接口，不能写死在前端。

## 7. Codex 禁止事项

- 禁止硬编码颜色值。
- 禁止为某个页面单独定义状态颜色。
- 禁止在业务组件内写客户 Logo。
- 禁止绕过 ThemeProvider。


## Codex 执行要求

- 开始实现前必须读取 `AGENTS.md`、`ai-coding/rules/frontend-rules.md` 和本规范。
- 不允许绕过 `packages/api-client` 直接调用 HTTP。
- 不允许在页面中硬编码中文、颜色、权限判断、状态判断。
- 新增页面必须同时补齐类型定义、API hooks、i18n key、权限点、基础测试和 Story/示例数据。
- 复杂页面必须输出 `PageAIContext`，供 AI 助手解释页面状态和下一步动作。
