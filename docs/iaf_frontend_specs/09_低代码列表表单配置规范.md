# 低代码列表与表单配置规范

## 1. 设计原则

IAF 第一版不做完整低代码运行时，但标准列表、表单、详情页必须支持配置驱动。复杂业务作业页仍然源码开发。

## 2. 列表配置能力

必须支持：

- 列显示 / 隐藏
- 列顺序
- 列宽
- 固定列
- 排序
- 筛选
- 查询条件保存
- 用户默认视图
- 共享视图
- 导出字段配置
- 状态标签渲染
- 操作列权限控制

## 3. 列表核心模型

```ts
type ListViewDefinition = {
  objectType: string;
  viewCode: string;
  columns: ListColumnDefinition[];
  searchFields: SearchFieldDefinition[];
  defaultSort?: SortDefinition[];
  actions: BusinessActionDefinition[];
};
```

## 4. 用户偏好

```ts
type UserListViewPreference = {
  userId: string;
  objectType: string;
  viewCode: string;
  visibleColumns: string[];
  columnWidths: Record<string, number>;
  searchValues: Record<string, unknown>;
  isDefault: boolean;
};
```

## 5. 表单配置能力

必须支持：

- 字段分组
- 字段显示 / 隐藏
- 字段只读
- 字段必填
- 字段默认值
- 字段顺序
- 字段宽度
- 字段联动
- 字段校验
- 简洁模式 / 专家模式

## 6. 表单核心模型

```ts
type FormDefinition = {
  objectType: string;
  formCode: string;
  sections: FormSectionDefinition[];
  modes: FormModeDefinition[];
};
```

## 7. 详情页配置能力

- 摘要字段配置
- Tab 配置
- 关联数据块配置
- 操作按钮配置
- 状态区配置
- 审批 / 审计 / 附件标准块

## 8. 源码生成关系

Codex 生成标准页面时，必须优先使用：

```text
ConfigurableListPage
ConfigurableFormPage
BusinessDetailPage
```

仅当任务明确要求复杂作业页时，才允许源码页面。


## Codex 执行要求

- 开始实现前必须读取 `AGENTS.md`、`ai-coding/rules/frontend-rules.md` 和本规范。
- 不允许绕过 `packages/api-client` 直接调用 HTTP。
- 不允许在页面中硬编码中文、颜色、权限判断、状态判断。
- 新增页面必须同时补齐类型定义、API hooks、i18n key、权限点、基础测试和 Story/示例数据。
- 复杂页面必须输出 `PageAIContext`，供 AI 助手解释页面状态和下一步动作。
